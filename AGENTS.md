## `/platform/numbers` — the by-the-numbers page

**The single most important rule for this page: never hardcode a number.** Every stat that renders on `nebbos.ai/platform/numbers` is read at build time from a JSON manifest under `content/`. The manifest is regenerated by scanner scripts under `scripts/`. If a number is wrong on the page, the fix is *always* in the scanner or the source data — never in the page.

### Files that compose it

| File | Role |
|---|---|
| `app/platform/numbers/page.tsx` | Server component. Reads JSON manifests, renders every section. Pure composition of primitives from `components/ui/`. |
| `lib/estate-stats.ts` | Shared TypeScript type contract for the manifests. `schemaVersion` pinned; additive-fields discipline. Both scanners and the page import from here. |
| `scripts/scan-estate.ts` | Current-snapshot scanner. Emits `content/estate-stats.json`. Runs `find`/`grep`/`wc`/`git` against every repo under `~/code/nebos-*` and `~/code/nebbos-*`. `pnpm tsx scripts/scan-estate.ts` — ~2 min. |
| `scripts/scan-estate-history.ts` | Historical time-series scanner. Walks each repo backward via `git worktree add --detach` at each month's end-SHA, runs full counters. Emits `content/estate-history/YYYY-MM.json` + rolled-up index + peaks. `pnpm tsx scripts/scan-estate-history.ts` — ~5 min. |
| `content/estate-stats.json` | Current-snapshot manifest. Overwritten by each scan-estate run. |
| `content/estate-history/*.json` | Monthly historical snapshots. One per month, append-only in practice. |
| `content/estate-history.index.json` | Rolled-up index — one small row per month with the chart-critical numbers. |
| `content/estate-peaks.json` | All-time peaks — concurrent operator sessions, single-day commit peak, worktrees. |

### When adding a new stat

1. **Add the counter to `scripts/scan-estate.ts`** (or the historical scanner if the stat needs a time series). Use existing helpers: `pathLinesByExt`, `grepCount`, `pathFindCount`, `commitsSince`, etc.
2. **Extend the type in `lib/estate-stats.ts`** — additive only. Bump `CURRENT_SCHEMA_VERSION` if the change is breaking.
3. **Re-run the scanner** to regenerate the JSON.
4. **Consume the new field in `app/platform/numbers/page.tsx`** via optional chaining (`stats.myNewField ?? 0`) so a stale manifest doesn't break the build.
5. **Verify** with `bash scripts/check-vocab.sh && pnpm next build`. `/platform/numbers` must remain a static prerender at ~172 B.

### Vocab discipline

The page passes through `scripts/check-vocab.sh` on every prebuild. The check-vocab hook flags any occurrence of forbidden marketing-surface vocabulary:

- **Never write `agent(s)` on the page.** The canonical vocabulary is `Pearl` (per-department entity), `company brain` (executive register), `operating system` (systems register), `architecture` (technical). See `content/brand.ts`.
- **Never write `tenant` on the page.** Use `company` / `per department` / `client isolation` per the four-tier scope model instead.
- **Never expose internal decision-record codes** on the marketing surface (ADR-*, PAT-*, GOV-*, FSR-*, PROV-*, NEB-XX-XX except in the doc's own colophon). If you need to preserve an anchor for future engineers, put it in an HTML comment: `<!-- ADR-234 -->`. The vocab-check ignores comments; engineers can grep them.
- **Never publish pricing.** Nebbos does not publish per-seat or per-transaction dollar figures. Enterprise conversation only.
